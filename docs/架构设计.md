# 极速看片 · 架构设计

本文面向开发者，说明整体架构、关键算法与实现取舍。使用方法见《使用说明》。

## 1. 总体架构

```text
┌────────────────────────────────────────────────────────────────┐
│  WebView（Svelte 5 前端）                                        │
│  App.svelte —— 播放游标 / 分页 / 断点记忆 / 事件 / 媒体管线分流   │
│              目录选择（dialog）/ X 键关目录（closeRoot）          │
│  VideoStage（画面舞台：旋转/缩放/拖拽/单击双击）                 │
│  ControlBar（两行式 + 音轨/字幕弹出菜单） / FileList（列表浮层）  │
│  HintScreen / InfoBar / HelpOverlay                              │
│  lib/format.js —— 时间/百分比 展示格式化                         │
│  lib/media.js —— 扩展名/语言标签/字幕同名匹配/HLS 清单重写        │
│  lib/subtitles.js —— WebVTT 统一出口（外挂 vtt/srt + 内嵌提取）  │
│  lib/filestream.js —— 顺序流式读取器（read_range 分块，v1.0.4）  │
│  lib/mp4/analyzer.js —— moov 定位 + 轨道信息（只读元数据区）     │
│  lib/mp4/mse-engine.js —— MSE 多音轨引擎（分段/节流/seek/切轨） │
│  hls.js（动态 import） —— m3u8 播放                              │
└───────▲──────────────────────────▲────────────────▲────────────┘
        │ invoke（IPC 命令）         │ asset:// 协议  │ fetch 整文件
        │  scan_directory            │ （媒体直读）   │ （仅 MSE 路径）
        │  read_range / stat_file    │                │
        │  load_state / save_state   │                │
        │  exit_app                  │                │
┌───────┴──────────────────────────┴────────────────┴────────────┐
│  Rust 后端（Tauri 2）                                            │
│  tauri-plugin-dialog  系统目录选择对话框（首页「+」按钮）        │
│  scanner.rs  递归扫描 + 自然排序 + 外挂字幕收集                  │
│  commands.rs read_range 按区间吐字节（moov 分析 / MKV 字幕流式） │
│  state.rs    会话状态持久化（位置 + 偏好）                        │
│  lib.rs      Builder 装配：插件注册 / 命令注册 / 窗口事件 / 兜底 │
└────────────────────────────────────────────────────────────────┘
```

职责划分原则：**Rust 负责「重 IO」（扫描、区间读字节、状态文件），前端负责「播放状态机」（游标、分页、断点表、媒体管线分流）**。媒体字节流一律走 asset 协议由 WebView 的 `<video>` 元素自己拉取；`read_range` 服务两类场景：moov / 轨道表等元数据区分析（几十 KB~几 MB），以及 MKV 内嵌字幕的手动提取扫描（4MB 块流式过 IPC，内存恒定，见 3.6）——除此之外播放期 mdat 不过 IPC。

**播放管线三分流**（本项目最核心的结构）：

- **原生**：单音轨 / 分析失败 / MSE 不可用 → `<video src=asset://…>` 直读，零额外开销，行为与极速听书的 `<audio>` 完全同构；
- **MSE 多音轨**：MP4 且音轨数 > 1 且 `MediaSource.isTypeSupported` 通过 → mp4box.js 整文件内存分段 + 双 SourceBuffer（详见 3.2）；任何一步失败自动回退原生；
- **HLS**：`.m3u8` → 清单重写后交给 hls.js（WKWebView 原生 HLS 优先直读）。

## 2. IPC 命令一览

| 命令 | 签名（要点） | 说明 |
|---|---|---|
| `scan_directory` | `async (root: String) -> ScanResult` | 递归扫描；传文件则自动取父目录；`spawn_blocking` 不卡 UI；同时收集各目录外挂字幕 |
| `read_range` | `(path: String, offset: u64, length: u64) -> Response(二进制)` | 按区间读字节（单次上限 8MB，越界钳制）；moov / 轨道表分析 + MKV 内嵌字幕流式提取（filestream.js 4MB 块循环调用），不经 JSON 序列化 |
| `stat_file` | `(path: String) -> u64` | 文件总大小（moov 尾部定位 / 字幕提取进度分母 / 大小预检用） |
| `load_state` | `() -> PlayerState` | 读取上次会话位置与全部偏好 |
| `save_state` | `(state: PlayerState) -> ()` | 保存位置与偏好（播放中防抖 1.2 秒调用） |
| `set_keep_awake` | `(active: bool) -> ()` | 播放期间阻止屏保 / 休眠的后备命令（Wake Lock API 不可用时由前端调用；幂等，见 power.rs） |
| `exit_app` | `(app: AppHandle)` | 兜底退出（正常退出走前端 `win.destroy()`） |

目录选择不占命令位：前端直接调 `@tauri-apps/plugin-dialog` 的 `open({ directory: true })`。

## 3. 关键算法

### 3.1 moov 定位与轨道分析（lib/mp4/analyzer.js）

```
前端：stat_file ─→ fileSize
                                          │ 顶层 box 游走（每次 read_range 16 字节头）
                                          ▼
      ┌── 顺序路径：ftyp → free → mdat(按 size 整体跳过) → moov ──┐
      │                                                          ▼
      │                                     moov 在文件头（faststart）：直接整块读取
      └── 走到 EOF 仍没见到 moov ──→ 尾部 16MB 特征扫描：
          从尾向前找 [size32][m o o v]，校验 pos+size == fileSize 后整块读取
                                          │
                                          ▼
      合成 24 字节 ftyp（isom）+ moov 连续缓冲 ──→ MP4Box.createFile(false)
      （只解析，不保留 mdat）        onReady(info)
                                          │
      ┌───────────────────────────────────┴──────────────────────┐
      ▼                            ▼                             ▼
  video{id,codec,宽高,fps}   audioTracks[{id,lang,codec,声道}]  subtitleTracks[{id,lang,codec}]
```

- **为什么合成 ftyp**：mp4box 的 `getInfo()` 会读 `this.ftyp.major_brand`，moov-only 缓冲会在 `appendBuffer` 内抛 TypeError（冒烟测试实测发现）。在 moov 前拼一个 24 字节最小 ftyp 即满足 getInfo，也不影响轨道表解析；
- **尾部扫描的校验**：`pos + size === fileSize` 排除 mdat 内部伪 `moov` 特征；
- **fps**：`nb_samples / 轨道时长`（VBR 下是平均值，逐帧步进够用）；未知时用 `requestVideoFrameCallback` 播放期实测，兜底 30。

### 3.2 MSE 多音轨引擎（lib/mp4/mse-engine.js）

与 mp4box.js 官方「on-the-fly fragmentation」同构，针对本地整文件场景强化：

```
fetch(整文件 ArrayBuffer) ──→ MP4Box.createFile(true)（保留 mdat，任意 getSample 可得）
        │ appendBuffer（onReady 同步触发）
        ▼
video.src = MediaSource(objectURL) → sourceopen → addSourceBuffer(video / audio)
        │
setSegmentOptions(视频轨, vq, {nbSamples:800}) + setSegmentOptions(音轨, aq, 同参)
（mp4box 约束：所有轨的 nbSamples 必须一致）
        │ initializeSegmentation('per-track') → 各轨独立 init segment
        ▼
start() ──→ onSegment(id, user, buffer, sampleNumber)
        │      ├─ 顺序追加进对应 SourceBuffer（updateend 队列驱动）
        │      ├─ releaseUsedSamples(id, sampleNumber)（内存稳定 ~1× 文件）
        │      └─ 节流：min(各轨前瞻) > 24s → stop()；播到剩 < 12s → start()
        ▼
loadedmetadata 到来后 load() 才返回（断点定位时 duration/currentTime 已就绪）
```

**四段踩坑记录 + v1.0.3 新增四段**（全部由冒烟测试 / 实测抓出）：

1. **`video.buffered` 是各 SourceBuffer 的交集**：切轨后音频轨清空，交集立刻为空、画面卡死——节流的前瞻计算必须取**各轨的最小值**，而不是只看视频轨；
2. **updateend 的 rogue 恢复**：seek/切轨的 flush 期间，remove 的 updateend 事件会触发 `_ensureGenerating` 在**旧轨道状态**上抢先 `start()`，把随后的定位彻底搅乱——用 `_seeking` 窗口拦截，收尾时**无条件** `start()`（`start()` 总会推进 `processSamples`，即使已处于启动状态）；
3. **`mp4box.seek()` 对全部轨道取最小落点**：字幕轨样本稀疏（几秒一条），会把落点拉偏到字幕样本处——改用 `seekTrack` 只对「视频 + 当前音轨」两条工作轨定位；
4. **RAP 对齐与逐帧步进冲突**：`useRap=true` 的 seek 会把小于一个 GOP 的位移吸回关键帧——已缓冲区内走快路径（直接返回目标时间，不清缓冲不重分段），逐帧步进因此精确落点；
5. **onSegment 的第 5 参 `last` 必须透传**（v1.0.3）：引擎用它标记轨道送完，丢掉这个参数会导致末尾收尾永不触发（见下）；
6. **末尾必须 endOfStream 收尾**（v1.0.3）：装载时声明的元数据时长（如 24.0s）往往比实际样本末尾（23.96s）长一点点，只 appendBuffer 不收尾，播放到样本尽头后在「时长未到」处无限等数据，`ended` 永不触发，**连播 / 快进触底全部失效**——两轨都送完且队列排空后把 duration 校准到实际缓冲末尾再 `endOfStream()`；seek / 切轨重灌数据后需重新收尾（appendBuffer 会自动把 ended 拨回 open）；
7. **`engine.ready` 必须接受 `readyState === 'ended'`**（v1.0.3）：收尾后若只认 'open'，切轨会被误判成「原生播放无法切换」——只有 'closed'（已销毁）才算不可用；
8. **`_doneTracks` 跨代污染**（v1.0.3）：轨道完成标记不能跨 seek / 切轨世代残留，否则节流暂停时（还没送完）就可能被旧标记触发收尾，把 duration 锁死在半途——慢 seek 清全部、同编码切轨只清音轨（视频轨未重灌、其 last 不会重报）。

**两段式精确 seek**：出缓冲区的跳转先粗定位到目标前最近的关键帧（RAP），记 `_pendingPrecise = 目标时间`；updateend / timeupdate 驱动 `_tryPreciseAdjust`，目标时间被两条轨的缓冲覆盖即自动精调（用户已播过目标点则放弃）。断点恢复因此能落回退出帧。

**切换音轨（v1.0.3 双路径）**：

- **同编码**（如双 AAC）：`unset(旧) → 清空音频 SourceBuffer → set(新) → 重新生成 init → seekTrack 把新轨单独定位到当前播放位置 → start()`。视频轨的 nextSample 与缓冲原封不动，画面零中断。
- **异编码**（AAC ⇄ Opus 等，v1.0.2 用户实测「切换后无声」的根因）：MSE 的 SourceBuffer 在创建时被 mime 里的 codecs 锁定，塞入另一种编码的 init 会触发解码管线错误；而 Chromium 对同一 MediaSource 有 SourceBuffer 数量上限，实测 `removeSourceBuffer(旧音频 SB)` 后 `addSourceBuffer(新编码)` 直接抛 `"reached the limit of SourceBuffer objects"`——**remove+add 换 SB 不可行**。可行方案是**整个 MediaSource 重建**：新建 MediaSource（全新 SB 配额）→ 视频 SB 沿用原编码、音频 SB 用目标编码 → 两条轨道重新 init + seekTrack 定位到切换前播放位置 → 恢复播放。画面快速重载一次（零点几秒），mp4box 实例与整文件缓冲全程复用，零二次读盘。
- 编码可用性由 `isAudioCodecSupported`（`MediaSource.isTypeSupported`）判定，App 层与引擎同源：不支持编码的轨在菜单置灰标注；默认轨只在支持轨里按语言偏好挑（v1.0.2 直接按语言挑默认轨，默认轨若是 AC-3 这类不支持编码，整个 MSE 装载直接失败回退原生，音轨切换完全不可用）。

### 3.3 HLS 本地化（lib/media.js rewriteHlsPlaylist + App.loadHls）

asset 协议把整个文件路径整体编码（`%2F` 不是路径分隔符），hls.js 按 URL 规则解析「相对分片名」时会丢目录（`/files/<全部编码的路径>/seg000.ts` 的「目录」只是 `/files/`）。解法：fetch m3u8 文本 → 按**文件系统路径**把每个非注释行（分片）与 `#EXT-X-KEY` / `#EXT-X-MAP` 的 `URI="…"` 属性解析为绝对路径 → `convertFileSrc` 重写 → blob URL 交给 `hls.loadSource`。hls.js 经动态 `import()` 单独分块（约 590KB），只在播放 m3u8 时加载。

### 3.4 字幕统一 WebVTT（lib/subtitles.js + lib/mkv/）

| 来源 | 路径 |
|---|---|
| 外挂 .vtt | `<track src=asset://…>` 直挂 |
| 外挂 .srt | fetch → 时间戳 `,` → `.` → 加 `WEBVTT` 头 → blob URL 挂 `<track>` |
| 外挂 .ass / .ssa | fetch → ass-compiler `compile()` 解析 → 斜体/粗体/下划线映射为 WebVTT 行内标签，`\N` → 换行，绘图指令整段丢弃 → blob URL |
| 内嵌 wvtt / tx3g | mp4box `setExtractionOptions` + `onSamples` 抽样（**必须在 onReady 里 `start()`，否则 processSamples 受 `sampleProcessingStarted` 保护不执行**——冒烟测试抓出）；`VTTin4Parser.getText` / `TX3GParser.parseSample` 解出文本 → cue 列表 → VTT 全文 → blob URL |
| 内嵌 MKV SRT / ASS | matroska-subtitles `SubtitleParser` 流式提取（v1.0.4：`read_range` 4MB 块流式喂入，内存恒定无大小限制）→ SRT 块文本即内容；ASS 块只有 Dialogue 最后一个字段，**重组完整 ASS 文档**（轨道 CodecPrivate 头 + 按块时间戳重建 Dialogue 行）再走 ass-compiler |
| HLS | hls.js `subtitleTracks` / `subtitleTrack` 自管 |

同一时刻只挂一条 `<track>`，切换即重建；`mode='showing'` 显示。MP4 内嵌提取优先复用 MSE 引擎的文件缓冲（零成本）；原生模式下手动选择时才整文件 fetch（前置 `stat_file` 超过 4GB 拒绝——mp4box 的 sample 提取要求字节全部驻留，流式化需重写其缓冲管理，列为后续工作）。MKV 内嵌为 read_range 流式提取（无大小限制，带进度与代次取消）。默认选轨策略：语言偏好 → 界面语言（中文），外挂优先于内嵌；内嵌自动选仅限 MSE 模式的 MP4（字节已在内存），MKV 内嵌（提取要扫全文件，大文件耗时数秒至数十秒）与原生模式 MP4 只允许手动选择。图形字幕（PGS / VOBSub / Kate 位图或未适配格式）在菜单置灰并说明。

### 3.5 画面舞台的变换数学（VideoStage.svelte）

- `<video>` 尺寸精确等于画面的**包含式显示盒**（原始宽高等比缩放、居中）——`rotate/scale/translate` 的变换原点即画面中心，旋转 90° 后不出空角；
- 变换链 `transform: rotate(R) scale(S) translate(P)`：屏幕位移 `d` → 画面位移 `e = R⁻¹·d / S`（顺时针旋转的逆变换），任意角度下拖拽跟手；
- 平移钳制：画面经 `rotate×scale` 后的包围盒与舞台求差，保证画面边缘不脱离舞台；回 1× 自动归零；
- pan 的 effect 钳制用「值不变不写 + untrack」双保险，杜绝「effect 读 pan 又写 pan」的自触发循环（Svelte 5 `effect_update_depth_exceeded`，冒烟测试抓出）；
- 单击 / 双击用 260ms 计时器区分；拖拽超过 4px 判定为拖拽、不再触发单击。pointerdown **在任何缩放级别都记录**（`press`），pointerup 时区分点击与拖拽；只有放大后才额外开启拖拽平移与指针捕获——早期版本 `press` 仅在放大时记录，导致默认缩放下单击 / 双击完全失效（冒烟测试新增派发式点击用例后抓出）。

### 3.5.1 全屏纯画面模式（App.svelte）

- 可见性派生：`infoShown / ctrlShown / listShown = !fullscreen && 对应 I/C/T 偏好`——`fullscreen` 一变，顶部信息栏、底部控制栏、右侧文件列表浮层**立即**全部隐藏（无论播放还是暂停），屏幕上只留视频画面；三个浮层的模板条件与 stage / list-overlay 的让位 padding 全部切换到派生值，非全屏时始终跟随偏好；
- 不再有闲置计时 / 活动浮现机制（v1.0.1 的 2.5s 方案在「断点续看默认暂停进入全屏」场景下两栏永不隐藏，被用户实测否定，v1.0.2 移除）：全屏中鼠标移动 / 点击 / 滚轮不触发任何浮现；键盘 / 滚轮操作照常可用；
- `I` / `C` / `T` 在全屏中仍切换偏好（持久化照常），效果在退出全屏后呈现；退出全屏（含 DOM 全屏被系统退出的 `fullscreenchange` 同步路径）无需额外处理，派生值自动恢复。

### 3.5.2 播放期间防屏保 / 休眠（lib/wakelock.js + src-tauri/src/power.rs）

- 前端 `wakelock.js` 双层策略：第 1 层 Wake Lock API（`navigator.wakeLock.request('screen')`，WebView2 / 较新 WKWebView 原生支持，页面隐藏时被系统自动释放，`visibilitychange` + `release` 事件双路重新申请）；第 2 层 WebView 不支持 / 被拒时 `invoke('set_keep_awake')` 走 Rust 后备；
- 异步序号 `seq` 丢弃过期结果（播放状态抖动时先到的申请不会覆盖后到的释放）；两层幂等，重复申请 / 释放无副作用；
- Rust `power.rs` 按平台分流（零新增依赖）：Windows 手工声明 kernel32 `SetThreadExecutionState`（ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED 挂在常驻线程上，发送端 drop 即复位）；macOS `caffeinate -dims -w <pid>`；Linux `systemd-inhibit --what=sleep:idle` 持锁期间循环确认本进程存活——三者都随进程退出自动解除，无系统级残留；
- 接入点：`$effect` 监听 `phase === 'view' && playing`，暂停 / 播完 / 关闭目录 / 组件销毁均自动解锁；三个平台分支均通过独立 crate 交叉 `cargo check`（Linux / x86_64-pc-windows-msvc / x86_64-apple-darwin）验证。

### 3.6 Matroska / WebM 支持（lib/mkv/，v1.0.3 新增）

**JS 包选型调研**（对应需求「查找和使用可用 JS 包」）：

| 候选包 | 评估结果 |
|---|---|
| matroska-subtitles@3.3.2 | **采用**：官方浏览器 bundle（147KB，内联 ebml-stream / readable-stream / buffer / pako 全部 polyfill）流式提取内嵌字幕，`tracks` / `subtitle` 事件模型清晰；但它是 webpack IIFE（顶层 var 挂 window、无模块导出），只能以经典 `<script>` 方式消费——vendor 目录固定版本 + 按需动态注入（首次遇到 MKV 才加载，其它格式零开销） |
| ass-compiler@0.1.16 | **采用**：ASS/SSA 解析为结构化 dialogue（slices → fragments，含样式继承），浏览器安全 ESM，正常 Vite 打包 |
| matroska@2.2.5 | 弃用：纯 Node（fs/http/util 依赖，无 browser 字段），WebView 前端不可用 |
| ebml / ebml-block | 弃用：仅底层解码且同为 Node 流式 API，轨道语义仍需自写 |
| libass-wasm | 弃用：7.7MB wasm + CJK 需另配字体，对本项目过重；ASS 走「ass-compiler + 纯文本富标签」轻量路线 |

**轨道分析（tracks.js，手写 EBML）**：Matroska 规范要求 Info / Tracks 位于第一个 Cluster 之前，因此只读头部即可拿到全部轨道——`read_range` 从 512KB 起步，Tracks 被截断则扩窗 4×（至 16MB 上限）。解析子集：EBML 头 → Segment（允许未知尺寸的两种形态：全 1 与 ffmpeg 的 `01 00…`）→ Info（TimecodeScale / Duration）→ Tracks（TrackEntry 的 TrackNumber / TrackType：1=视频 2=音频 0x11=字幕 / CodecID / Name / Language / Video / Audio）。出口结构与 analyzeMp4 对齐，App 层管线无感知差异。

**两个实测踩坑**（EBML 数值语义，写成注释留在代码里）：

1. **8 字节 vint 超出 JS 安全整数**：「先按整数读完整 vint 再减标记位」在 2^56 量级被浮点舍入（实测 82 被读成 80，整棵树错位）——必须按字节剥标记位再累积；未知尺寸也按字节比对（全 1 / 01+全 0），不做整数等值判断；
2. **未知尺寸两种形态**：RFC 8794 的全 1，与 ffmpeg 的「仅标记位 + 其余全 0」（实测本仓库测试媒体即此形态，一度导致永远找不到 Segment）。

**字幕提取（subtitles.js + ass.js，v1.0.4 流式化）**：v1.0.3 的实现是「整文件读入单个 ArrayBuffer（≤4GB，前置 `stat_file` 预检）→ 64KB 假分块喂入」——用户实测 5GB MKV 即被护栏拒绝（根因：V8 单 ArrayBuffer 约 4GB 硬上限，且整文件驻留有 OOM 风险）。v1.0.4 改为**真流式**：`filestream.js` 的 `readFileChunks` 异步生成器循环调 `read_range`（4MB/块，钳制在 Rust 端 8MB 上限内），拿到一块喂一块 `SubtitleParser`，跨块的残缺 EBML 元素由 parser 内部缓冲拼接——内存占用恒定在「单块 + 解析状态 + 已收集字幕文本」（~10MB 量级），**与文件大小无关，无任何大小限制**；每块之间有一次 IPC await 天然让出主线程，播放中提取不冻结 UI。提取耗时只受磁盘顺序读速度限制（5GB ≈ SSD 数秒 / HDD 数十秒）。App 层配套：`subExtractGen` 代次（再次选择 / 换文件 / teardown 即取消，被取消的静默丢弃）、状态栏百分比进度。保险丝从单一 12s 总时限重构为两级：喂入间隙看门狗（30s，防磁盘 / IPC 卡死）+ `end()` 后 finish 收尾时限（15s）。转换逻辑不变：按轨道号收集块 → SRT / WebVTT 块文本即内容；ASS 块只有 Dialogue 的最后一个字段，**重组完整 ASS 文档**（轨道 CodecPrivate 头 + 按块时间戳重建 Dialogue 行，图层 / 样式 / 边距等字段全部还原）再交给 ass-compiler 解析出富文本 cue；单轨无内容与图形字幕（PGS / VOBSub）给出明确错误信息。

**音频切换边界**：Chromium 原生 Matroska 解码器不支持运行期切轨（WebView 的 `<video>` 无音轨 API），MKV 音轨菜单仅展示（含编码名），选择时提示受限——这与 MP4 原生回退模式行为一致。

### 3.7 分页文件列表（App.svelte + FileList.svelte）

与极速听书同款：`flat[]`（播放序列，纯 JS）与 `lines[]`（分页行，`$state`）在 `buildList` 一次建成；`lineOfIdx[flatIdx] → 行号` 供锚定；`pageSize = floor(浮层高度 / 24)`；只渲染当前页。差异：回车在本程序是播放 / 暂停，翻页改为点击浮层底部页码指示（环形）。

### 3.8 断点记忆（App.svelte + state.rs）

- `positions: Map<绝对路径, 毫秒>` 全程维护；`syncCurrentPosition()` 在换文件前 / 暂停时 / 防抖保存时入账，规则：`<1s` 或 `距末尾<1s` 删除条目，其余写入；
- 换文件时 `playIndex` 先 `syncCurrentPosition()` 再改游标；`pendingSeek = { idx, sec, autoplay }` 挂起，`loadedmetadata` 后核对游标再定位（MSE 模式由 `loadMedia` 统一定位，避开装载中途的时序问题）；
- 恢复会话：`openRoot(root, state)` 精确匹配 `file` → 定位到 `position_ms` 且 **autoplay=false**；文件已不存在则从第一个文件自动播放；
- 保存链路三层：① 播放中防抖 1.2s；② 前端 `onCloseRequested`（preventDefault → 保存 → destroy）；③ Rust `WindowEvent::CloseRequested` 兜底 flush。`closeRoot` 会 `clearTimeout` 作废防抖中的保存；
- `X` 键按「目录前缀 + 路径分隔符」精确匹配清除（`/movies/a` 不会误伤 `/movies/ab`）。

### 3.9 播放引擎（App.svelte）

- 唯一的 `<video>`（VideoStage 常驻挂载，元素全生命周期唯一，MSE / HLS 挂载后不被替换）；`volume` 映射滑杆 / 快捷键（0~1 步进 0.05）；`muted` 临时状态不持久化；
- 进度文字由 `timeupdate` 节流驱动（不再需要听书的 rAF 波形循环），同一回调顺带驱动 MSE 节流恢复与精确落点（`engine.tick()`）；
- 自动播放被拦截时 toast 提示按空格开始；`error` 事件只提示不跳下一曲（防坏文件失控连跳）；
- `loadGen` 代次防护：快速连续切文件时，旧管线的一切异步结果（分析 / MSE 装载 / onFail 回退）都会被代次校验丢弃。

## 4. Tauri 2 要点（踩坑记录）

| 事项 | 配置 | 说明 |
|---|---|---|
| asset 协议 | `app.security.assetProtocol: { enable: true, scope: ["**", "**/*"] }` | 媒体直读的前提；**必须**同时给 `tauri` crate 开 `features = ["protocol-asset"]` |

## 5. 前端状态机

```
phase: hint ──drop / 「+」选目录──→ scanning ──成功──→ view（空结果 → empty；异常 → error）
  ▲                                      │                    │
  ├── 重新拖拽 / 重新点「+」 ◀────────────┴──── 拖入/选新目录 ◀──┘（openRoot 重新走流程）
  │
  └── X 键 closeRoot（清空序列/断点/记忆指针，保留偏好）◀── view / empty / error

view 内部（非响应式纯 JS 状态）：
  flat[] / lineOfIdx[] / subsByDir        —— 播放序列 / 分页锚定 / 外挂字幕索引
  engine(MseEngine) / hls / mediaInfo      —— 媒体管线三态（native | mse | hls）
  pendingSeek / loadGen                    —— 挂起断点定位 / 加载代次（防旧结果覆盖）
  fpsKnown / rVFC 计数                     —— 帧率（分析值 → 实测值）

view 内部（$state 响应式）：
  cursorIdx / currentPage / pageSize / pageCount —— 导航与分页
  playing / curTime / duration / volume / muted
  rotation / zoom / fullscreen             —— 画面状态（前两者持久化）
  audioOptions / audioValue / subOptions / subValue —— 菜单数据
  positions（Map）                          —— 每文件断点
  infoVisible / ctrlVisible / listVisible / helpVisible —— 浮层开关
```

`flat`、engine 等高频大数据刻意**不放进 Svelte 响应式**；仅渲染相关状态用 `$state`。
